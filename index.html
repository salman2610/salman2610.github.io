How I work — six steps, from first recon to the retest.
01

Recon

Asset discovery, enumeration, technology fingerprinting. Understand what actually exists before deciding what to test.

$ nmap -sV -p- target.example
443/tcp open https nginx 1.24
22/tcp open ssh OpenSSH 9.2
+ 14 subdomains found

Map

Attack surface mapping and threat modelling — what's reachable, what's exposed, and what actually matters if it breaks.

entry points ▸ 38 routes · 9 forms
trust bounds ▸ user → api → database
risk order ▸ auth > upload > admin

Test

Manual and tool-assisted testing against the OWASP Top 10 — Burp Suite and Nmap as a starting point, not the whole method.

$ GET /api/orders?id=1'
← 500 SQL syntax error near "'"
⚑ injection candidate · OWASP A03

Exploit

Validate real impact safely, in scope, with evidence. A finding isn't a finding until it's proven, not just flagged by a scanner.

$ id=1 UNION SELECT user()
← app_rw@db-internal
✔ impact proven · read-only · in scope

Report

Every finding CVSS-scored and reproducible — a report your team can act on without a follow-up call to ask what it means.

FINDING-07 SQL injection
CVSS 8.1 High · A03:2021
✔ steps · evidence · fix attached

Remediate

Fix guidance mapped to each finding, then a retest. A report nobody acts on was never worth writing.

- query("… id = " + id)
+ query("… id = ?", [id])
✔ retest passed · finding closed

A normal web application.A login page, a dashboard, an API behind it. Nothing looks wrong.

Every one has an attack surface.Each form, endpoint, upload and integration is a door someone can try.

Recon.I map what's exposed: domains, subdomains, open ports and the tech behind them.

Enumeration.I probe each service for users, endpoints, versions and hidden paths.

Discovery.I find where the logic breaks: weak auth, injection points, misconfigurations.

Exploitation.I prove the impact safely, in scope, with evidence. Not just a scanner alert.

Remediation.I write the fix, hand it to your developers, and retest until it holds.
